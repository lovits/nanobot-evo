# NanoEvo 工具调用选择准确率

## 结论

基于 3 个市场 Skills、6 条真实仓库分析轨迹，共检查 73 次带参数的工具调用：

| Skill | 正确调用 | 总调用 | 准确率 |
| --- | ---: | ---: | ---: |
| codebase-survey | 25 | 25 | 100.00% |
| analyzer | 19 | 19 | 100.00% |
| source-code-analysis | 28 | 29 | 96.55% |
| **合计** | **72** | **73** | **98.63%** |

唯一明确的错误调用来自 `source-code-analysis`：Agent 在只读仓库分析任务中通过
`exec` 执行了 `pip install -e .`。该调用会修改 Python 环境，不符合实验的只读约束，
也不是完成静态仓库分析所必需。

## 判定规则

一次调用同时满足以下条件才计为正确：

1. 工具属于仓库分析需要的只读工具集合。
2. 工具执行成功。
3. `read_file` 的目标确实是文件，`list_dir` 的目标确实是目录。
4. `exec` 没有执行安装、删除、移动、写入或 Git 工作区修改命令。
5. 同一条轨迹中没有完全相同的重复调用。

本指标准确名称是“已发生调用的工具选择准确率”，计算公式为：

`合规、目标正确且非重复的已发生调用数 / 已发生调用总数`

它能回答“Agent 已经发出的这个调用是否合理”，但不能单独回答“Agent 是否漏掉了本应
调用的工具”。后者属于工具调用召回率，需要为每个任务预先标注必要工具集合。

## 可复现结果

机器可读结果见 `tool-selection-accuracy-20260728.json`。实验采集器已增加结构化
`tool_calls` 字段，后续新实验会直接保存工具名、参数、状态、结果摘要和错误，不再只能
依据工具名做粗粒度判断。
